## v1.1.10

这一版主要是**杂记**的改造，外加一个同步根因修复的完整验证。

### 1. 修：同一大任务下的小任务杂记会互相盖掉

以前任务杂记的文件名是`日期_大任务名.md`，同一天在同一个大任务下写第二条，
就落到同一个文件上、**把前一条直接覆盖掉**。

现在**一条杂记一个文件**：撞名就往后再排一个（`…-2.md`、`…-3.md`）。
老文件一个字节都不动、照样读得出来，编辑老杂记仍然是原地写回 ——
升级不需要迁移，也不会丢内容。

### 2. 杂记页和待办页同构

- 任务杂记按**大任务**分组，每条带进度条和完成数（和待办读的是同一份数据）；
- 小任务那一行能直接勾（勾完待办那边也是勾的，反过来一样）；
- **点小任务 → 看它名下所有杂记**（跨月份，现读盘），可以就地编辑、删除、再写一条；
- 日记那一段保持原样，还是按天分组。

顺带：杂记多记了一个「小任务 ID」，小任务改了名也认得出旧杂记（老杂记没有 ID，
就退回按标题认）。

### 3. 桌面端可以把图片拖进杂记里

拖进来 → 图片复制进 vault 的`附件/年月/`（重名自动加序号）→ 正文光标处自动插入
`![](附件/…)`，预览和阅读时按当前 vault 解析成磁盘图。图找不到会给一行占位提示，
不会把整页搞崩。安卓端没有文件拖拽，这个功能只做在桌面端。

### 4. 修：同步「只能下载、无法上传」（根因 + 完整验证）

**根因**：服务端可能因为权限/配额/路径问题**拒绝写入，却照样回一个成功状态码**；
我们据此把状态记成「已同步」→ 下次同步认为本地干净、云端更新 →
**把云端旧内容下载回来盖掉本地新改的**。

**修法**：上传之后立刻**回读**一次，比对哈希；不一致就当失败 —— 状态不更新、
本地保持「脏」，下次重试上传，绝不反向覆盖。下载覆盖本地之前另有一道哈希复核，
对不上就当冲突处理。

**这一版把验证补全了**（以前只验到「同步完成」，那正是这个 bug 藏得最深的地方）：

- 用真的 WebDAV 服务器（本机 wsgidav）+ 两个独立目录互为两端；
- **本地改一个文件 → 同步 → 直接去服务器把文件读回来比对**，两端逐字节相同；
- 再包一个「说谎的后端」（PUT 只回 ETag、根本不写）：上传被回读校验当场识破、
  状态不被污染、本地的**新内容没有被云端旧内容盖掉**、下次仍然重试上传；
- 反过来演示一遍：手工把状态改成「已同步」，下一次同步就会把旧内容下载回来盖掉
  本地 —— 正是当年那个现象，证明这条防线是承重的。

25 项全过，完整记录存 `docs/同步验证-真服务器-2026-09-30.txt`。

> 注意：验证是在**本机 WebDAV** 上做的（路径编码、条件写、三态判定、读回校验
> 全部走的是真实 HTTP）。**你的坚果云账号还没实测过** —— 升级后第一次同步建议
> 先在一台设备上做，同步完去坚果云网页端看一眼文件内容对不对。

### 5. 顺手清掉的

- 日历里「日记会存到 杂记/202609/日记/…md」这种把文件路径写进提示的文案删掉了；
- portable 包从这一版起是**真正的 zip**（以前那个其实是 tar，双击往往打不开）。
